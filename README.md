# Computer Graphics Lab 00

Mesh shader 와 path tracing 을 사용하는 실시간 렌더러. 비교를 위한 고전 VS/FS 파이프라인 경로를 함께 제공한다.

## 요구 사항

- C++20 컴파일러 (MSVC 19.3x / Clang 16+ / GCC 13+)
- CMake 3.25 이상, Ninja
- [Vulkan SDK](https://vulkan.lunarg.com/) 1.3 이상 (셰이더 컴파일러와 검증 레이어)

vcpkg 는 최초 CMake 구성 시 `external/vcpkg` 에 고정 태그로 자동 클론/부트스트랩된다. 별도 설치가 필요 없다.

## 빌드

```sh
cmake --preset debug                        # 최초 구성 시 vcpkg 의존성 빌드로 수 분 소요
cmake --build --preset debug                # 빌드
cmake --build --preset debug --target run   # 빌드 후 바로 실행
```

구성, 빌드, 테스트를 한 번에 하려면 `cmake --workflow --preset debug` 를 쓴다.
빌드된 실행 파일은 `build/debug/cg_lab` 에 있으므로 인자를 줄 때는 직접 실행한다.

`release` 프리셋은 RelWithDebInfo 로 구성된다. `ctest --test-dir build/debug` 로 자체 점검을 돌린다.

### 플랫폼

macOS(MoltenVK)와 Windows 를 대상으로 한다. Windows 쪽에서 특별히 챙긴 것은 셋이다.

- **경로**: `platform/windows/cg_lab.manifest` 가 프로세스 ANSI 코드 페이지를 UTF-8 로 고정한다.
  이게 없으면 한글이 섞인 경로에서 `std::filesystem::path::string()` 이 깨지거나 예외를 던지고,
  그 문자열을 그대로 받는 `fopen` / cgltf / stb_image 가 파일을 열지 못한다. Windows 10 1903 이상이
  필요하다. 매니페스트는 콘솔 출력 코드 페이지까지 바꾸지는 않아서 `main` 에서
  `SetConsoleOutputCP(CP_UTF8)` 을 따로 부른다. 로그가 한글이라 이걸 빼면 `cmd.exe` 에 깨져 나온다.
- **줄바꿈**: `.gitattributes` 가 저장소를 LF 로 고정한다. `core.autocrlf` 가 켜진 Windows 에서
  받아도 CRLF 가 커밋에 섞이지 않는다. 소스에 CRLF 가 들어와도 glslc 와 nlohmann-json 은 그대로
  읽으므로 동작에는 문제가 없지만, 저장소를 한 형식으로 두는 편이 낫다.
- **경로 문자열 비교**: `path::native()` 는 Windows 에서 `std::wstring` 이라 좁은 문자열 리터럴과
  섞어 쓸 수 없다. 장면 저장의 상대 경로 판정은 `generic_string()` 으로 한 번 바꿔 두 플랫폼에서
  같은 코드로 처리한다.

Vulkan SDK 를 압축만 풀어 쓰는 환경을 위해 `VK_LAYER_PATH` 를 채워 주는데, **실제로 있는
디렉터리일 때만** 지정한다. 레이어 매니페스트 위치가 배포판마다 달라서, 없는 경로를 넣으면 로더가
시스템에 설치된 레이어까지 못 찾아 오히려 망가진다.

| `--no-occlusion` | 두 패스 오클루전 컬링을 끈다. 켠 것과 스크린샷을 비교할 때 쓴다 |

| `--fixed-dt <초>` | 벽시계 대신 이 값을 프레임 간격으로 쓴다. 물리·애니메이션·노출 적응·시간축 누적이 실행마다 같아진다 |

장면 뷰 위에서 마우스 오른쪽 버튼을 누른 채 WASD/QE 로 카메라를 움직인다. 장면 전환은 계층 패널의
드롭다운이나 숫자 키로 한다. 기동 시 장면은 방향광 하나뿐인 빈 `GameScene` 이다. 모델은 메뉴
`파일 › 모델 불러오기…` 나 `--model` 로 올린다.

메뉴바는 Unity 편집기와 같은 자리에 있다. `파일`(새 장면 Ctrl+N, 장면 열기 Ctrl+O, 장면 저장 Ctrl+S,
모델 불러오기, 미사용 모델 해제), `편집`(되돌리기·다시 실행, 복제 Ctrl+D, 삭제 Delete, 부모 해제),
`오브젝트`(빈 오브젝트, 기본 도형, 메쉬, 조명), `설정`(렌더 설정 창 여닫기), `창`(배치 초기화). 가운데의
`재생`/`정지`(Ctrl+P)는 물리 시뮬레이션을 돌리고, 정지하면 재생 전 상태로 돌아간다.

기즈모 조작은 `W` 이동, `E` 회전, `R` 크기이며 `Ctrl` 을 누른 채 끌면 스냅이 걸린다. 스냅 간격은
장면 뷰 툴바에서 조작 종류별로 고치고, `스냅` 을 체크하면 늘 걸린다. 렌더 설정은 도킹되지 않는 떠 있는
창이라 열어 둔 채 장면을 돌려 볼 수 있고, 그룹을 접거나 검색 칸에 그룹 이름을 쳐 그 그룹만 볼 수 있다.

계층 패널은 오브젝트의 부모-자식 구조만 보여준다. 항목을 끌어다 다른 항목 위에 놓으면 부모가 바뀌고,
노드 밖 어디에 놓아도 뿌리로 올라간다. 부모가 바뀌어도 화면에서의 위치는 그대로 유지된다. 부모를 옮기거나
숨기면 자손이 함께 따라가며, 지우거나 복제할 때도 자손이 함께 처리된다. 노드를 우클릭하면 복제·삭제·부모
해제·자식 추가가, 빈 공간을 우클릭하면 오브젝트 만들기와 모델 불러오기가 뜬다.

`모델 불러오기` 는 `public/assets` 의 glTF 목록과 직접 입력한 경로에서 모델을 런타임에 불러와 현재 장면에
붙인다. 모델 하나가 계층의 뿌리 하나가 되고 그 아래에 프리미티브별 오브젝트가 달린다. 적재할 때
지오메트리 버퍼 전체를 다시 만들기 때문에 장치가 한 번 멈춘다.

인스펙터는 이름, 변환, 그리고 붙어 있는 부품(메쉬 렌더러, 조명, 애니메이터, 강체, 유체)을 헤더마다
보여준다. 헤더 오른쪽의 `제거` 로 부품을 떼고, 맨 아래 `컴포넌트 추가` 로 붙인다. 메쉬 렌더러는
메쉬를 바꿀 수 있고, 강체를 붙이면 메쉬의 경계 구가 콜라이더 크기가 된다.

## 기본 도형

`asset::primitives` 가 평면·큐브·구·구(정이십면체)·원기둥·콘·캡슐·토러스를 코드로 만든다. 편집기
«오브젝트 › 기본 도형» 에서 붙이고, 장면 파일에는 `<builtin:box>` 같은 이름으로 적힌다.

전부 glTF 와 **같은 경로**를 탄다. `buildLodHierarchy` 로 meshlet 과 LOD DAG 를 만든 뒤
`GeometryStore` 에 올린다. `meshLive` 가 LOD 항목 수로 살아 있는 메쉬를 가리므로 이 단계를 건너뛴
메쉬는 그려지지도, 메뉴에 나오지도 않는다.

크기는 «경계 구»가 아니라 «축 정렬 크기»로 맞춘다. 모두 ±1 정육면체 안에 들어가고 적어도 한 축이 그
벽에 닿는다. 경계 구를 맞추면 정육면체가 구보다 훨씬 작아 보인다. 기준이 반지름 1 인 것은 내장 구가
예전부터 그랬고 유체 입자가 그 크기에 기대기 때문이다.

유체 입자는 정이십면체 구를 쓴다. 위도·경도 구는 극에 삼각형이 몰려 수만 개를 그릴 때 조명이 고르지
않았다. 삼각형 수는 320 대 352 로 비슷하다.

감기 방향은 눈으로 보기 전에는 틀린 줄 모르고, 틀리면 면이 컬링되어 통째로 사라진다. `primitives`
테스트가 삼각형마다 기하 법선과 정점 법선의 방향을 견줘 그것을 잡는다.

## 모델 적재

편집기의 «모델» 단추로 여는 glTF 는 **백그라운드 스레드**가 해석한다. 파싱, 정점 변환, 텍스처
디코딩, LOD 계층 구축까지가 그 스레드 몫이고, 끝나면 메인 루프가 프레임 사이에 GPU 업로드와 장면
연결만 한다. 그동안 창은 계속 돌고, 화면 아래에 단계와 진행률이 뜬다. 적재 중에 또 요청하면 줄을
서서 차례로 처리한다. 시작 인자 `--model` 과 장면 파일이 가리키는 모델은 결과가 바로 필요하므로
같은 코드를 타되 끝날 때까지 기다린다.

- 진행률 단위는 단계마다 다르다. 정점 변환은 프리미티브, 텍스처는 장 수, LOD 는 단계마다 절반씩
  줄어드는 인덱스 수를 어림한 값이다. 파일 파싱과 GPU 업로드는 끝을 몰라 흐르는 막대로 보인다.
- 적재가 끝나면 로그에 단계별 시간이 남는다. 다음 병목을 찾을 때 이걸 먼저 본다.
- 정점 변환은 프리미티브 단위로 워커에 나누고 속성마다 접근자를 통째로 푼다. LOD 구축은 메쉬끼리
  나누고 그 안의 그룹도 다시 나눈다(작업 큐가 여러 생산자를 받는다). 메쉬 하나 안의 0 단계 분할과
  단계별 파티션은 아직 직렬이라, 메쉬가 하나뿐인 큰 파일에서는 그 부분이 남는다.
- 기동 시 `public/assets` 를 읽는 것은 아직 동기다. 렌더러가 지오메트리 버퍼를 전제로 만들어지기
  때문인데, 그때는 창에 아무것도 그리지 못하므로 큰 에셋은 편집기에서 여는 편이 낫다.

적재기는 파일이 준 속성(위치·노멀·탄젠트·UV, 스킨이면 가중치까지)이 완전히 같은 정점을 **하나로 합친다**.
스캔 데이터는 삼각형마다 정점을 따로 두는 일이 많은데, 그대로 두면 meshlet 이 삼각형 124 개가 아니라
정점 64 개 한도에 먼저 걸려 삼각형 21 개짜리로 잘게 쪼개지고 단순화는 모든 변을 경계로 보고 잠근다.
합치기는 노멀·탄젠트를 만들기 **전**에 한다. 만든 뒤에 하면 사본마다 인접 삼각형이 하나뿐이라 값이
달라져 합쳐지지 않는다. 삼각형 5 만 개짜리 언인덱스 격자가 150 만 정점에서 25 만으로 줄어 인덱스 판과
같은 meshlet 수와 LOD 시간이 나온다.

두 단계로 한다. 먼저 속성이 완전히 같은 정점을 합치고(화면 그대로), 그다음 **위치와 UV 가 같은 정점을
노멀이 스무딩 각도(기본 30°) 안이면 합쳐 노멀과 탄젠트를 평균** 낸다. 삼각형마다 정점을 따로 두고 노멀을
조금씩 다르게 적은 스캔 데이터가 여기서 줄어든다. 노멀을 키에 그대로 두면 프리미티브 경계가 전부 열린
모서리로 남아 meshlet 이 정점 한도에 먼저 걸리고 단순화가 그 자리에서 멈춘다. 각도 밖의 정점(각진
모서리)은 따로 남기고, 노멀이 없는 프리미티브는 어차피 합친 뒤에 만들어지므로 묶음을 통째로 합친다.
`--weld-angle 0` 이면 첫 단계만 한다. 로그에 세 수가 «정점 → 같은 속성 합침 → 위치·UV 합침» 으로 남는다.
대표 노멀은 묶음의 첫 정점이라 클러스터 안의 퍼짐은 각도의 두 배까지 될 수 있고, 탄젠트 손 방향이 다른
정점(거울 UV 이음새)은 합치지 않는다. 일부러 각을 세운 저폴리 메쉬는 각도보다 작은 모서리가 부드러워지니
그런 에셋은 0 으로 연다.

정점 버퍼는 원본 정점 하나뿐이고 **모든 LOD 단계와 meshlet 이 그것을 공유**한다. meshlet 은 자기가 쓰는
정점의 전역 번호 목록을 갖고, mesh shader 가 지역 인덱스를 그 목록으로 풀어 정점을 읽는다. 고전 경로와
광선 경로는 목록을 풀어 둔 인덱스 버퍼를 쓴다. 전에는 meshlet 마다 정점을 복제해 두어 경계 정점과 LOD
단계마다 사본이 생겼고, 헬멧 하나가 원본 정점의 3.6 배였다. 단순화 결과가 원본 정점 번호를 그대로
가리키므로 상위 LOD 단계도 새 정점을 만들지 않는다.

- 정점을 공유하니 정점만으로는 어느 meshlet 인지 모른다. mesh shader 는 자기가 그리는 meshlet 을 알고,
  고전 경로는 간접 그리기 명령마다 그 명령이 그리는 meshlet 번호를 따로 두어 `gl_DrawID` 로 읽는다.
  컴퓨트 컬링은 명령 하나가 meshlet 하나라 정확하고, CPU 가 만든 LOD 단위 명령은 그 단계의 첫 meshlet
  으로 대표하므로 meshlet 디버그 뷰가 오브젝트 단위로 보인다. LOD 디버그 뷰는 어느 쪽이든 맞다.
- 푸시 상수가 128 바이트에 꽉 차서 디버그 뷰 번호는 카메라 버퍼로 옮겼다.
- 스킨 인스턴스의 meshlet 경계 구 컴퓨트도 같은 목록으로 변형 정점을 찾는다.
- meshlet 안의 8비트 지역 인덱스는 uint32 하나에 넷씩 묶어 두고 mesh shader 가 비트 이동으로 꺼낸다.
  8비트 스토리지 기능 없이도 되고 uint32 로 펼치던 때보다 4 배 작다.

지오메트리 버퍼는 업로드하고 나면 **CPU 사본을 남기지 않는다**. 모델이 더해지면 GPU 버퍼를 새 크기로
잡고 옛 내용을 GPU 안에서 옮긴 뒤 새 모델 몫만 스테이징으로 올린다. 그 순간 GPU 에는 옛 버퍼와 새
버퍼가 함께 있다. 메쉬·재질·meshlet 표는 렌더러가 CPU 에서도 읽으므로 그대로 둔다.

정점은 **28 바이트**다. 위치는 float 셋, 노멀과 탄젠트는 8진법(octahedral) 매핑으로 snorm16 둘씩, UV 는
float 둘이다. 탄젠트의 손 방향은 y 성분의 최하위 비트에 넣는다. UV 를 half 로 줄이면 [0.5, 1) 구간의
간격이 1/2048 이라 4K 텍스처에서 텍셀 두 개씩 어긋나므로 float 로 둔다. 스킨 조인트와 가중치는 정점에서
떼어 스킨 메쉬만 갖는 버퍼로 옮겼다. 접고 푸는 계산은 `src/asset/vertex_pack.h` 와
`shaders/scene_types.glsl` 이 같은 식이어야 하며, 스킨 컴퓨트는 풀어서 돌린 뒤 다시 접는다.
`vertex_pack` 테스트가 왕복 오차를 0.02도 아래로 확인한다.

모델을 올리기 전에 **GPU 메모리 예산**과 견준다. 지오메트리와 텍스처가 차지할 바이트에, 버퍼를 키우는
동안 옛 버퍼와 겹치는 만큼을 더해 `VK_EXT_memory_budget` 이 알려 주는 남은 예산보다 크면 사유를
로그에 남기고 올리지 않는다. 예산을 넘겨 올리면 할당은 시스템 메모리로 넘어가 통과하지만 그 위에서
가속 구조를 세우거나 그리다가 장치를 잃는다. 삼각형 5,500만 개짜리 스캔이 그렇게 죽었다.
`--gpu-budget` 으로 예산을 직접 줄 수 있다.

### 미리 압축된 텍스처 (KTX2)

PNG/JPEG 는 RGBA8 로 풀어 올리고 GPU 가 밉을 만든다. 큰 모델은 텍스처를 **KTX2 에 BC 로 미리 압축**해
두는 편이 낫다. 디코딩이 없어 적재가 빠르고 GPU 메모리가 4~8 배 준다. glTF 는 `KHR_texture_basisu`
로 KTX2 이미지를 가리키고, 적재기는 파일 앞의 KTX2 식별자를 보고 가른다.

- 읽는 것: 초압축 없는 KTX2, 2D 한 장, BC1/BC3/BC4/BC5/BC7 또는 RGBA8, 담긴 밉을 그대로 씀. Basis
  Universal 이나 zstd 로 초압축된 파일은 트랜스코더가 없어 사유를 남기고 뺀다.
- 만드는 법: KTX-Software 의 `ktx create --format BC7_SRGB_BLOCK --generate-mipmap in.png out.ktx2`
  (노멀 맵은 `BC5_UNORM_BLOCK`). 파일의 색 공간은 무시하고 재질 슬롯으로 sRGB 여부를 정한다.
- 노멀 맵이 BC4/BC5 면 재질에 두 채널 플래그가 붙고 셰이더가 z 를 복원한다.
- 압축 포맷은 블릿할 수 없어 밉이 파일에 있어야 한다. 한 단계만 있으면 그 단계로만 샘플링한다.
- `textureCompressionBC` 가 없는 장치에서는 폴백 없이 텍스처를 빼고 경고한다.

LOD 계층을 만들 때 그룹마다 `meshopt_simplify` 를 부르는데, 이 함수는 **넘긴 정점 수에 비례해**
배열을 만들고 훑는다. 그룹은 수백 정점인데 메쉬 전체를 넘기면 호출마다 메쉬 전체를 다시 읽는
셈이라, 정점 2천만 개 메쉬에서는 그룹 하나에 0.6 초가 들었다. 그래서 그룹이 쓰는 정점만 모아
지역 번호로 압축한 뒤 부르고 결과를 되돌린다. 오차는 `meshopt_SimplifyErrorAbsolute` 로 월드
단위를 주고받는다. 상대 오차는 넘긴 정점의 범위 기준이라 그룹마다 뜻이 달라지기 때문이다. 삼각형
2백만 개 격자에서 적재가 126 초에서 2.5 초로 줄었다. 정밀도가 그룹 범위 기준으로 잡히면서 단순화가
더 깊이 진행되어 LOD 단계 수가 조금 늘고, 자동 LOD 화면이 미세하게 달라질 수 있다. 0 단계는 그대로다.

## 스키닝 애니메이션

glTF 의 스킨과 애니메이션을 읽어 매 프레임 조인트 행렬을 만들고, **스킨 컴퓨트**가 그 행렬로
정점을 옮겨 변형 정점 버퍼에 써 둔다. 정점 셰이더, mesh 셰이더, 그림자 패스, 광선 경로(하위 가속
구조와 적중 셰이더)가 전부 이 버퍼를 읽는다. 스키닝을 한 곳에서만 하므로 래스터와 광선 추적이 같은
포즈를 보고, 정점 셰이더는 조인트를 몰라도 된다. 재생 상태는 모델마다 하나씩 있으며 인스펙터의
애니메이션 컨트롤러에서 다룬다.

- 조인트 번호를 스킨 가중치 버퍼에 바이트 하나로 담으므로 스킨 하나에 조인트는 256 개까지다. 가중치는
  정점과 떼어 두어 스킨이 없는 메쉬는 그 자리를 쓰지 않는다.
- 변형 정점 버퍼는 반쪽 둘로 나뉜다. 반쪽 0 이 현재, 1 이 지난 포즈로 고정이고, 포즈가 바뀐
  오브젝트만 현재 구간을 지난 쪽에 복사한 뒤 다시 스킨한다. 그래서 모션 벡터가 관절 움직임까지 담고,
  포즈가 그대로인 오브젝트는 지난 위치 = 현재 위치(관절 변위 0)다. 스킨 오브젝트 목록이 바뀌거나 버퍼가
  커진 프레임에는 지난 포즈가 없어 강체 이동만 남는다.
- 포즈가 그대로인 오브젝트(재생이 꺼졌거나 속도 0)는 스킨 컴퓨트·meshlet 경계·하위 가속 구조 구축을
  전부 건너뛴다. 신호는 `Scene::animatorPosed` — 애니메이터가 이번 프레임에 실제로 재포즈했을 때만 참이고,
  클립과 시각이 지난 프레임과 같으면 재포즈 자체를 건너뛰어 거짓이다.
- 스킨 인스턴스의 meshlet 경계 구는 변형 정점에서 다시 잰다. 절두체와 오클루전 컬링은 그 구로 하고,
  법선 원뿔은 바인드 포즈 기준이라 건너뛴다.
- 스킨 하위 가속 구조는 포즈가 바뀐 오브젝트 것만 다시 세운다. 현재 반쪽이 고정이라 그대로인 오브젝트의
  구조는 여전히 맞는 자리를 가리킨다.

## 가림 컬링

meshlet 단위 오클루전 컬링은 **두 패스**로 돈다. 프레임을 넘어 살아남는 meshlet 가시성 비트 버퍼를
두고, 1차 패스는 지난 프레임에 보였던 meshlet 만 (이번 프레임 LOD·절두체·원뿔로 다시 걸러) 그린다.
그 깊이로 HZB 를 만들고, 2차 패스는 지난 프레임에 안 보였던 meshlet 을 HZB 로 판정해 새로 보이게
된 것만 이어 그린다. 2차는 1차 집합도 다시 판정해 비트를 갱신하므로 한 번 보인 meshlet 이 영원히
1차에 남지 않는다.

이전 프레임 HZB 로 한 번에 판정하던 방식은 카메라가 빠르게 움직이면 가장자리에 한 프레임 늦게
나타나는 팝인이 있었다. 두 패스는 이번 프레임 깊이로 판정하므로 그 지연이 없다. 대가는 렌더 패스를
한 번 끊었다 잇는 것과 컬 디스패치·HZB 구축이 프레임 중간으로 들어오는 것인데, HZB 는 어차피
만들던 것이라 순증은 아니다. 2차 패스는 대개 비어 있거나 가장자리 몇 개다.

비트가 낡아도 렌더는 옳다. 낡은 1 은 1차의 드로우 낭비만 낳고, 낡은 0 은 2차가 다시 판정한다.
그래서 인스턴스 슬롯이 재배치되거나 장면이 바뀌어도 비트를 지우지 않고, 버퍼가 커질 때만 0 으로
채운다. mesh shader 경로(태스크 셰이더)와 컴퓨트 컬링 경로가 `culling.glsl` 의 같은 함수를 쓴다.
`--debug 9` 로 어느 패스가 그린 화소인지, `--orbit` 으로 회전 중 팝인 유무를 볼 수 있다.

## 더티 플래그

장면은 프레임마다 `refresh()` 에서 **지난 사본과 필드를 직접 비교**해 변한 것을 찾고, 세계 변환과
가시성 캐시를 다시 만든다. 훅을 거는 대신 비교하는 이유는 `Object::transform` 이 public 이라 편집기
여러 곳에서 직접 대입하기 때문이다. 훅은 빠뜨릴 수 있지만 비교는 빠뜨릴 수 없다. 덤으로 나오는
오브젝트별 더티 플래그는 이후 그림자 시점 무효화에 쓴다.

- 부모 사슬을 오브젝트마다 서너 번 다시 타던 것이 프레임당 한 번 순회로 줄었다.
- 정지한 애니메이터는 포즈 계산 자체를 건너뛴다.
- 경로 추적 누적과 가속 구조는 장면이 실제로 바뀔 때만 다시 만든다.

## 프로파일러

렌더 설정 패널의 `구간 계측` 을 켜면 패스별 CPU/GPU 시간을 잰다. GPU 는 타임스탬프 쿼리로 재고,
결과는 같은 프레임 슬롯을 다시 쓸 때 대기 없이 읽는다. 꺼져 있으면 구간 함수가 분기 하나로 돌아와
Vulkan 호출도 할당도 하지 않는다.

`--profile` 로 시작하면 처음부터 켜지고, 종료할 때 결과를 로그로 남긴다. 창을 볼 수 없는 실행에서
쓴다. 타임스탬프를 지원하지 않는 장치에서는 CPU 구간만 나온다.

## 장면 파일

메뉴 `파일 › 장면 저장…` / `장면 열기…` 로 현재 장면을 `public/scenes` 아래 JSON 으로 다루며,
glTF 가 아니라 이 저장소만의 형식이다. 오브젝트의 부모-자식 구조와 변환, 조명, 애니메이터의 재생
상태, 강체·유체 부품의 설정, 카메라와 환경광을 담는다.

메쉬는 전역 번호가 아니라 (모델, 모델 안의 메쉬) 짝으로 적히고 모델 경로는 `public/assets` 기준
상대 경로라, 다시 열 때 필요한 glTF 만 골라 올린 뒤 번호를 새로 잇는다. 장면이 쓰지 않는 모델은
파일에 들어가지 않는다. 코드로 만든 기본 도형은 `<builtin:sphere>` `<builtin:box>` 처럼 적힌다. `version`
은 3 이고, 더 새로운 판은 거절하되 옛 판은 빠진 키를 기본값으로 읽는다. 판 2 이하의
`bloomIntensity` 만 예외로 버리고 새 기본값을 쓴다. 그 값의 뜻이 «섞는 비율»에서 «더하는 세기»로
바뀌어 그대로 읽으면 번짐이 거의 보이지 않기 때문이다(0 은 뜻이 같은 «끔»이라 그대로 둔다).

## 에셋 해제

모델은 어느 장면도(그리고 편집기의 되돌리기 기록도) 가리키지 않게 되면 GPU 에서 내려간다. 오브젝트를
지우거나 장면을 옮긴 프레임에 모든 장면의 메쉬 렌더러와 애니메이터를 훑어 참조 없는 모델을 찾는다.
되돌리기 기록이 아직 그 모델을 들고 있으면 되살릴 수 있으므로 기록에서 밀려날 때까지 기다린다. 메뉴
`파일 › 미사용 모델 해제` 는 기록을 비우고 바로 내린다.

메쉬 번호는 장면과 기록이 들고 있어 옮기지 않는다. 해제된 메쉬는 항목만 비운 무덤으로 남고, 정점·인덱스·
meshlet 배열의 구간은 빈 구간 목록에 들어가 다음 모델이 재활용한다. 꼬리가 비면 다음 업로드 때 버퍼가
실제로 줄어든다. 텍스처는 이미지가 지워지고 bindless 번호가 다시 쓰인다. 무덤 메쉬는 하위 가속 구조도
세우지 않는다.

## 물리

재생 중에만 돈다. 시작할 때 장면을 떠 두고 정지하면 그 상태로 돌아가므로, 재생 중의 움직임은 되돌리기
기록에 쌓이지 않는다.

**강체**도 CPU 와 GPU 중 하나로 돈다. 부품의 `백엔드` 가 `자동`이면 CPU 다 — GPU 솔버는 골라야 돈다.
두 솔버는 `physics::collectRigidBodies` 로 **같은 세계 상태**를 펴고 접촉도 **같은 규칙**으로 만든다.
갈리는 것은 접촉을 푸는 방식뿐이다.

**CPU 솔버**(`src/physics/rigid_body.cpp`)는 구·상자·무한 평면·원기둥·캡슐·메쉬 콜라이더를 세계 공간에서
반암시적 오일러로 적분하고, 접촉을 순차 임펄스(반발·마찰)로 8 회 푼 뒤 Baumgarte 위치 보정을 8 회 돌려
오브젝트의 지역 변환에 되돌려 쓴다. 1/120 초 고정 간격으로 프레임당 최대 8 스텝. 적분과 광역 검사는
작업 큐에 나눈다. 광역은 유체와 같은 **균일 해시 격자**(`physics::collectPairs`, `src/physics/spatial_hash.h`)
다: 셀 = 2·최대 경계 반지름이라 닿을 수 있는 짝은 이웃 27 셀 안에 있고, 평면은 무한이라 격자 밖 목록으로
동적 물체 전부와 짝을 이룬다. 버킷은 계수 정렬이라 용량이 없고, 짝은 (i, j) 오름차순으로 정렬해 워커 수와
무관하게 같은 순서로 푼다(순차 임펄스는 순서에 따라 결과가 갈린다). GPU 솔버는 `rigid_grid.comp` 가 같은
격자를 원자 카운터로 짓고(버킷 64, 넘치면 그 물체는 빠진다), 물체마다 후보를 모아 번호순으로 정렬한 뒤
누적하므로 O(n²) 루프와 부동소수 결과가 같다.

상자끼리는 **여섯 면 축의 분리축 검사**로 가장 얕게 겹치는 축을 찾고, 그 축에서 겨루는 면 안에 든
상대 꼭짓점을 접촉으로 낸다(최대 네 점). 서로의 꼭짓점이 상대 안에 들어왔는지로만 보면 크기가 같은
상자를 쌓았을 때 꼭짓점이 옆면에 딱 붙어 «가장 얕은 면» 이 옆으로 잡히고 침투가 0 이 되어 서로를
그대로 통과한다. 위치 보정은 같은 짝의 여러 점 가운데 **가장 깊은 하나**로만 민다. 넷을 다 밀면 네 배로
튀어 오른다. 모서리끼리 비스듬히 걸치는 경우(축 아홉 개)는 여전히 놓친다.

**원기둥·캡슐**(축은 오브젝트의 +Y, `반지름` 과 `반높이`)이 낀 짝은 분리축이 아니라 **표본 기반**이다.
모양마다 표면의 «찔러 보는 점» 을 두고(구는 중심, 상자는 꼭짓점 여덟, 캡슐은 두 끝과 상대를 향한 축 위
점, 원기둥은 뚜껑 중심·테두리 표본 열여섯·상대 방향의 테두리 두 점) 상대 표면의 가장 가까운 점
(`physics/collider_shapes.h` 의 `closestOn*Local`)까지의 거리가 반지름보다 짧으면 접촉이다. 양쪽을 서로
찔러 깊은 네 점을 남긴다. 모양 기하는 유체 CPU 백엔드와 GLSL(`shaders/collider_shapes.glsl`)이 같은 것을
쓴다. GJK/EPA 같은 볼록 형상 일반 해법이 아니라 표본 사이로 파고드는 얇은 모서리는 놓칠 수 있다.

**메쉬** 콜라이더는 오브젝트의 Mesh Renderer 가 그리는 메쉬를 그대로 쓴다. 바닥·지형용이라 **늘 운동학**
이고, 상대(구·상자·원기둥·캡슐)의 표본점을 삼각형마다 본다(`closestOnTriangleSurface`). 앞면 쪽은 구 대
삼각형이고, 뒷면으로 조금 들어간 점은 앞면 법선으로 밀어 올려 한 스텝에 뚫은 점이 계속 내려가지 않게
한다. 삼각형은 모델을 올릴 때 `scene::ColliderMesh` 에 CPU 사본으로 남기는데, 삼각형 수가 2048 이하인
**가장 고운 LOD 단계** 하나만 담는다. 굵은 단계는 화면의 메쉬와 조금 어긋나지만 BVH 없이 삼각형을 전부
훑는 협역 검사가 감당할 크기다. GPU 솔버는 세계 공간 삼각형을 강체와 함께 올려 같은 판정을 한다. 유체는
메쉬 콜라이더를 통과한다(입자 대 삼각형은 아직 없다).

**GPU 솔버**(`src/gfx/rigid_body_gpu.cpp`, `shaders/rigid_*.comp`)는 같은 접촉을 **Jacobi** 로 푼다.
순차 임펄스는 접촉을 하나씩 «지금까지 고친 속도» 위에 풀기 때문에 순서에 매인다. 여기서는 물체마다
이웃 전부와의 접촉을 같은 속도로 풀어 한 번에 더하고, 읽는 배열과 쓰는 배열을 나눠 순서 의존을 없앤다.
수렴이 느려 반복을 16 회로 늘렸지만 그래도 쌓인 물체가 CPU 보다 조금 더 물렁하다. 마찰 원뿔의 한계도
쌓인 임펄스가 아니라 이번 반복의 임펄스로 재므로 그만큼 약하다. **두 백엔드의 수치는 같지 않다.**
인스펙터가 그 사실을 적어 둔다.

상태는 **GPU 에 머문다.** 결과를 되읽으려면 그 프레임이 끝나야 하는데 기다리면 GPU 와 CPU 가 번갈아
멈추므로, 되읽기는 세 프레임 뒤에 받아 오브젝트 변환에 되쓴다. 매 프레임 장면에서 다시 올리면 그 지연만큼
뒤로 감기기 때문에, 장면 쪽 값이 우리가 되쓴 것과 달라졌을 때만(부품 추가·삭제, 편집기 조작, 재생 시작)
다시 올린다. 되쓰기는 `Scene::refresh` **앞**이라 세계 변환 캐시가 그 값으로 다시 만들어진다.

**유체**는 GPU 컴퓨트 SPH 와 CPU SPH 중 하나로 돈다. 부품의 `백엔드` 가 `자동`이면 GPU 를 쓰되 컴퓨트
파이프라인을 만들지 못한 장치에서는 CPU 로 내려간다. `CPU` 를 고르면 언제나 CPU 다. 인스펙터가 «지금
무엇이 도는지» 를 함께 보여 준다.

두 백엔드는 **같은 상수**(`physics::deriveFluidParams`)와 **같은 서브스텝 규칙**(`physics::fluidSubsteps`)을
쓰고, 해시 격자도 같은 규칙(고정 용량 버킷 + 원자 카운터)으로 짓는다. 두 벌로 두면 백엔드를 바꿀 때마다
물이 달리 흐른다. CPU 쪽은 밀도·힘·적분을 작업 큐로 나누고 격자를 `std::atomic_ref` 로 채워 잠금이 없다.
같은 시작 상태에서 워커 수와 무관하게 같은 결과가 나온다(`fluid` 테스트가 그것을 본다).

CPU 백엔드는 입자 인스턴스를 매핑된 버퍼에 CPU 가 직접 쓴다. 배치는 `fluid_instances.comp` 와 같으므로
래스터도 경로 추적도 GPU 백엔드와 똑같이 본다. 스텝은 «유체» 노드가 이번 프레임의 인스턴스·표면을 다 쓴
뒤 백그라운드 스레드로 띄우고 다음 프레임 머리에서 거둔다. 그래서 주 스레드가 스텝을 기다리지 않는 대신
물이 한 프레임 늦게 보이고, 콜라이더도 띄운 시점의 것을 본다. 스텝 자체는 그대로라 `--fixed-dt` 면
실행마다 같은 결과다.

이 아래는 GPU 백엔드 이야기다(`src/gfx/fluid.cpp`, `shaders/fluid_*.comp`). 입자 상태는 GPU 에만 있고
장면의 유체 부품은 백엔드, 방출 상자, 입자 수·반지름, 커널 반지름, 기준 밀도, 강성, 점성, 용기, 중력만
갖는다.
서브스텝마다 해시 격자를 원자 카운터로 다시 짓고(고정 용량 버킷, 잠금 없음), 밀도·압력을 구한 뒤
압력·점성·중력으로 적분하며 용기와 강체(구·상자·평면·원기둥·캡슐, 일방향, 메쉬 제외)에 부딪힌다. 서브스텝 수는 강성과 커널
반지름에서 어림한 안정 간격으로 정한다.

### 물 표면

부품의 `표시` 를 `표면` 으로 두면 입자 대신 **마칭 큐브**로 뽑은 등치면을 그린다. 용기를 덮는 격자에
입자 커널을 합쳐 스칼라 장을 만들고, 셀마다 등치면 삼각형을 내어 정점 버퍼 꼬리에 이어 붙인다. 자리는
원자 덧셈 하나로 잡으므로 잠금이 없고, 정점 수는 `VkDrawIndirectCommand` 의 첫 칸에 그대로 쌓여
간접 그리기가 읽는다. GPU 백엔드는 `fluid_field.comp` + `fluid_marching.comp`, CPU 백엔드는
`physics::buildFluidField` + `physics::marchFluidField` 가 **같은 표**(`shaders/marching_cubes.glsl` ↔
`src/physics/marching_cubes.cpp`)로 같은 버퍼를 채운다. 그리기 경로는 하나다.

케이스 표는 손으로 옮겨 적은 것이 아니라 «면의 윤곽은 그 면의 네 꼭짓점 부호만 보고 정한다» 는 규칙에서
만들어 냈다. 면을 맞대는 두 셀이 같은 네 값을 보므로 윤곽이 반드시 같아지고, 그래서 고전 표에서 생기는
틈이 없다. `marching_cubes` 테스트가 그 성질(활성 모서리, 감기, 방향 일관성, 면 윤곽의 결정성, 셰이더
표와의 일치)을 표에서 직접 다시 확인한다.

격자의 **가장자리 표본은 0** 으로 둔다. 용기를 가득 채운 물은 벽에 닿은 표본이 전부 높아 등치면이
안쪽에서 끊기고, 그러면 옆면이 없는 «뚜껑만 있는» 표면이 나온다.

그리기는 두 패스다. 먼저 앞뒤 면을 모두 그려 «뒷면 거리 − 앞면 거리» 를 가산 혼합으로 쌓아 **두께**를
얻고(겹친 층까지 더해진다), 그 두께로 Beer-Lambert 흡수를 내어 표면을 그린다. 표면 패스는 **하늘 뒤**에
와서 배경이 이미 색상 대상에 들어 있고, **미리 곱해진 알파**로 섞으므로 화면 색 사본을 뜨지 않는다.
재질 평가는 다른 표면과 같은 `lighting.glsl` 함수를 쓴다.

표면 패스는 세 번 그린다. 두께 → **깊이 프리패스**(앞면만, 가장 가까운 물 표면의 깊이를 박는다) →
표면(`VK_COMPARE_OP_EQUAL`). 프리패스가 없으면 마칭이 내놓는 삼각형 순서가 프레임마다 달라 한 화소가
한 번 섞이기도 두 번 섞이기도 해서 물이 깜빡인다. 정점 셰이더의 `gl_Position` 은 `invariant` 다.

한계 넷을 인스펙터와 주석에 적어 두었다. ① 혼합이 알파 하나로만 뒤를 가려 파장별 투과를 그대로 낼 수
없다(물빛은 흡수량에 물 색을 곱해 더한다). ② 그림자를 **받지도 던지지도** 않는다 — 받는 쪽은
`shadow.glsl` 이 장면 푸시 상수 블록을 이름으로 참조하는데 표면 패스에는 그 블록이 없어서고, 던지는 쪽은
표면으로 바꾼 유체의 입자 드로우를 꺼서다. ③ **Ray Traced Reflections 는 물 표면을 «반사 + 물빛» 으로 본다.**
반사 컴퓨트는 확정 히트의 customIndex 표식으로 물을 가려 `FluidSurfaceInfo` 에서 정점을 읽고, 래스터 물 표면과
같은 `water_shading.glsl` 로 셰이딩한다. 재귀가 없어 반사 안의 물 뒤는 굴절로 보지 않고 물빛으로 가린다. 물
표면 자체에서 출발하는 반사 광선은 없다(표면이 반사 가중치를 0 으로 덮는다). ④ 정점 상한
(`FLUID_MAX_SURFACE_VERTICES`)을 넘으면 넘친 자리에서 잘린다. 두 백엔드가 «처음 넘친 자리» 로 자르는 규칙까지
같다.

**Path Tracing 은 물 표면을 굴절로 추적한다.** 표면 모드에서는 입자 구 대신 물 표면의 **하위 가속 구조 하나**를
TLAS 에 올린다(`RayTracer::ensureDynamicBottomLevel`/`buildDynamicBottomLevel`). 삼각형 수는 GPU 카운터에만
있어 두 길이 있다: 장치가 간접 구축(`accelerationStructureIndirectBuild`)을 지원하면 마칭이 함께 채운 범위
구조체(`surfaceRange`)에서 읽고, 아니면(NVIDIA) **상한 개수로 세운다** — 그래서 마칭 전에 정점 버퍼를 0 으로
지워 쓰지 않은 꼬리가 퇴화 삼각형이 되게 한다(CPU 백엔드는 memset). 인스턴스의 customIndex 는 유체 번호에
표식 비트(`FLUID_SURFACE_CUSTOM_INDEX`)를 얹은 것이고, 적중 셰이더는 그 표식을 보면 인스턴스·메쉬·재질 표 대신
`FluidSurfaceInfo`(정점 주소, 물 색·거칠기, 흡수 계수)에서 정점을 바로 읽는다. 광선 생성 셰이더는 물 히트에서
유전체 프레넬(굴절률 1.33)로 반사·굴절 가운데 하나를 고르고, 물 안을 지나는 구간마다 Beer-Lambert 로
`absorption × 두께 배율 × 거리`만큼 먹인다. 물빛은 래스터처럼 더하는 색이 아니라 **투과율이 낸다.** 물 통과는
바운스 예산을 먹지 않고(들어가 나오는 데 두 번이 든다) 따로 8 회로 묶인다. 그림자 광선(경로 추적·래스터 광선 질의)은
마스크 0xFE 로 물을 지나가므로 물이 딱딱한 그림자를 던지지 않는다(물속 어두움은 굴절 경로의 흡수가 낸다). 뒷면 컬링은 물 인스턴스만
끈다(안에서 나가는 광선이 뒷면을 맞혀야 한다).

ponytail 셋. 굴절에 거칠기를 넣지 않았고, 굴절률 변화의 복사 휘도 배율(eta²)은 들어갔다 나오며 상쇄된다고 보아
생략했으며, 상한 개수 구축은 실제 삼각형 수와 무관하게 프레임마다 65536 삼각형을 세운다.

두 백엔드의 장 값은 완전히 같지는 않다. GPU 는 해시 격자의 버킷당 32개까지만 보고 해시가 충돌하면 같은
입자를 두 번 더한다. CPU 는 입자 전부를 정확히 훑는다. 같은 등치값에서 표면 두께가 조금 다를 수 있다.
CPU 백엔드는 표본마다 입자 전부를 훑으므로 격자 해상도가 `FLUID_MAX_CPU_SURFACE_RESOLUTION` 으로 묶인다.

```sh
./build/release/cg_lab --open tests/scenes/fluid_surface.json --play --screenshot gpu.png --screenshot-frame 200
./build/release/cg_lab --open tests/scenes/fluid_surface_cpu.json --play --screenshot cpu.png --screenshot-frame 200
```

두 장면은 백엔드만 다르다(`rigid_cpu.json`/`rigid_gpu.json` 과 같은 규칙). `--debug 2`(노멀)로 찍으면
마칭 큐브가 만든 면을 그대로 볼 수 있어 표면 자체를 확인하기 좋다.

입자는 내장 구 메쉬의 **인스턴스**로 그린다. 프레임 끝의 컴퓨트가 입자마다 `Instance` 를 렌더러의
인스턴스 버퍼 꼬리에 직접 쓰고, 오브젝트 명령 뒤에 인스턴스 드로우 하나가 붙는다(모든 래스터 경로에서
고전 정점 셰이더로 그린다). 광선 기능이 켜져 있으면 상위 가속 구조 인스턴스도 같은 컴퓨트가 버퍼 앞쪽에
써 두어 경로 추적과 광선 질의 그림자·반사에도 입자가 보인다. 입자가 움직이는 프레임은 장면이 바뀐 것으로
쳐 그림자 캐시와 경로 추적 누적을 버린다.

물리를 확인할 장면은 편집기에서 만든다. 바닥으로 쓸 오브젝트에 `메쉬 › 구` 를 붙여 납작하게 눌러 놓고
운동학 상자 강체를, 그 위에 구 몇 개에 동적 강체를, 빈 오브젝트에 유체를 붙인 뒤 `장면 저장…` 으로
`public/scenes` 에 저장한다(그 폴더는 사용자 자료라 저장소에 담기지 않는다). 그 파일을
`--open <경로> --play --screenshot-frame 120` 으로 열면 창 없이 결과를 볼 수 있다.

## 콜라이더 표시

강체 부품이 붙은 오브젝트는 콜라이더를 초록 선으로 덧그린다(구는 세 축의 원, 상자는 열두 모서리,
무한 평면은 격자 한 장, 원기둥은 두 원과 세로선 넷, 캡슐은 거기에 반원 넷, 메쉬는 콜라이더가 실제로 보는
굵은 LOD 의 삼각형 전부). 유체는 용기를 청록, 방출 상자를 노랑으로 그린다. 고른 오브젝트만 밝다.
렌더 설정의 `콜라이더 표시` 로 끄고, 실행 인자 `--no-colliders` 로도 끈다.

**톤 매핑과 공간 업스케일이 끝난 표시 해상도**에 그린다. 그 앞에 그리면 노출과 업스케일이 선 색을
흔들고, 시간축 업스케일이 잔상을 남긴다. 대신 깊이 첨부물을 쓸 수 없어(표시 해상도와 렌더 해상도가
다르다) 프래그먼트가 렌더 해상도 깊이 버퍼를 텍스처로 읽어 가림을 판정한다. 역깊이라 값이 클수록
가깝고, 장면보다 뒤면 지운다. `가림 판정` 을 끄면 늘 보인다.

콜라이더의 세계 공간 크기는 `scene::colliderPose` 가 정한다. 구는 배율 중 가장 큰 축을 받고 상자는
축마다 따로 받으며 원기둥·캡슐은 반지름이 X·Z 중 큰 배율, 반높이가 Y 배율을 받는데, 솔버(`physics::stepRigidBodies`)와 표시가 같은 함수를 쓰므로 «보이는 것»과
«부딪히는 것»이 어긋날 수 없다.

## 카메라

기본은 **궤도(orbit)** 다. 오른쪽 단추로 대상 주위를 돌고, 휠로 확대하고, 가운데 단추로 대상을
끌고 다닌다. 위치는 `대상 - 시선 * 거리` 로 계산하므로 어떻게 돌려도 대상을 놓치지 않는다.
계층에서 오브젝트를 고르고 **F** 를 누르면 그 오브젝트가 궤도 중심이 된다.

장면 뷰 위 도구 막대에서 **자유(fly)** 로 바꾸면 1인칭처럼 날아다닌다. 오른쪽 단추로 시선을 돌리고
`WASD` 또는 **방향키**로 이동, `Q`/`E` 또는 `PageUp`/`PageDown` 으로 오르내리고, `Shift` 로 4배
빨라진다. 휠은 위치가 아니라 **이동 속도**를 바꾼다. 자유 모드에서 위치를 휠로도 옮기면 조작이 두
갈래가 되어 헷갈린다.

키보드 이동은 마우스가 장면 뷰 위에 있을 때만 받는다. 그렇지 않으면 인스펙터에 값을 입력하다
카메라가 움직인다. 모드를 오갈 때는 시선과 위치를 그대로 이어 화면이 튀지 않는다.

조작 방식과 궤도 중심, 거리도 장면 파일에 함께 저장된다. 중심이 없는 옛 파일은 보고 있던 앞쪽 한
점을 중심으로 삼는다.

## 조명과 그림자, SSAO

조명은 오브젝트에 달리는 부품이라 계층에서 위치와 방향을 기즈모로 다룰 수 있다. 방향광, 점광,
스폿광, 영역광 네 가지를 지원하며 인스펙터에서 색, 세기, 거리, 원뿔 각, 영역 크기를 조절한다.
영역광은 직사각형을 대표점으로 근사한다.

그림자 시점마다 캐스터를 두 단계로 거른다. 먼저 **광원 절두체**로 자르고, 남은 것은 경계 구를 광
진행 방향으로 끌어 만든 캡슐이 **카메라 절두체**에 닿는지 본다. 화면 밖 캐스터도 그림자는 보일 수
있어 카메라 절두체만으로는 버릴 수 없기 때문이다. 캡슐은 양 끝이 **모두** 평면 밖일 때만 버린다.

컬링은 CPU 에서 오브젝트 단위로 한다. 이 저장소의 컴퓨트 컬링은 meshlet 단위 명령을 뱉는데, 압축
간접 그리기(`drawIndirectCount`)가 없는 장치에서는 상한만큼 발행해야 해서 시점 하나에 수백 개의
무효 드로우가 생긴다. 그림자는 오브젝트 단위 드로우가 훨씬 싸다. 압축 간접 그리기가 있는 장치라면
시점을 컬 컴퓨트의 두 번째 디스패치 축으로 넘겨 meshlet 단위까지 거르는 편이 낫다.

그림자는 알파 경로마다 파이프라인을 나눠 그린다. 불투명 캐스터는 프래그먼트 셰이더 없이 그려
조기 깊이 판정을 온전히 쓰고, 컷오프 캐스터만 기저 색 알파를 읽어 `discard` 한다. 하드웨어가
`depthClamp` 를 지원하면 켜서, 그림자 절두체 근평면 앞의 캐스터가 잘려 나가지 않게 한다.

그림자 맵은 1024×1024 층 16장짜리 **2D 배열 이미지**다. 타일 아틀라스를 쓰지 않으므로 PCF 가
타일 경계를 넘을 걱정이 없고, 해상도와 시점 수가 정사각 격자에 묶이지 않는다. 스폿광은 층 하나,
점광은 여섯 면을 차지하고, 층이 모자라면 남은 조명은 그림자를 만들지 않는다. 영역광은 반구 전체로
빛을 내보내 시점 하나로 담을 수 없어 그림자를 만들지 않는다. 표본은 3×3 PCF 로 걸러진다.

방향광은 **캐스케이드**(기본 4단, 1~4 조절)를 쓴다. 분할은 균등과 로그를 λ 로 섞는 PSSM 이고,
캐스케이드마다 부분 절두체의 **최소 포함 구**를 해석적으로 구해 씌운다. 이 구는 카메라 회전에
불변이라 고개를 돌려도 그림자 가장자리가 흔들리지 않는다. 광 시점 행렬은 **평행이동 없는 회전만**
쓰고 구 중심을 텍셀 격자에 스냅한다. 광원을 카메라 쪽으로 옮겨 가며 스냅하면 격자가 카메라를
따라다녀 스냅이 무의미해지기 때문이다. 노멀 오프셋 바이어스는 캐스케이드의 월드 텍셀 크기에
비례한다. 가까운 캐스케이드는 텍셀이 수 mm, 먼 쪽은 수십 cm 라 고정값으로는 양쪽을 맞출 수 없다.
프래그먼트는 카메라까지의 **반지름 거리**로 캐스케이드를 고른다. 축 거리보다 크거나 같아 항상 더
넓은 쪽을 골라 보수적으로 안전하다. `디버그 뷰 > 캐스케이드` 로 어느 픽셀이 어느 단을 쓰는지,
`> 그림자` 로 가시성만 따로 볼 수 있다.

층은 **시점별로 캐시**한다. 텍셀 스냅 덕에 카메라가 텍셀 하나보다 적게 움직이는 동안에는 캐스케이드
행렬이 비트 단위로 같고, 그러면 그 층은 렌더 패스를 아예 시작하지 않는다. 타일 기반 GPU 에서
`loadOp = LOAD` 로 깊이 버퍼를 되읽는 것보다 패스를 건너뛰는 편이 싸기 때문에 아틀라스를 배열로
바꾼 것이기도 하다. 얼마나 먹히는지는 솔직히 갈린다. 캐스케이드 0 은 텍셀이 몇 mm 라 카메라가
움직이는 내내 더티고, 먼 캐스케이드와 정지한 스폿·점광이 이득을 낸다. 이 저장소의 장면에서는
그림자 패스가 0.593 ms 에서 0.294 ms 로 줄었다(캐스케이드 4단을 켠 채로).

SSAO 는 깊이에서 법선을 복원해 반해상도로 계산한 뒤 4×4 상자 흐림을 거쳐 환경광에만 곱해진다.
이전 프레임 깊이를 쓰므로 카메라가 빠르게 움직이면 한 프레임 늦게 따라온다.

### 하이브리드 광선 그림자 (선택 경로)

`VK_KHR_ray_query` 를 지원하는 장치에서는 **카메라 가까운 곳만 광선으로** 가시성을 판정하고 먼 곳은
그림자 맵을 그대로 쓴다. 가까울수록 그림자 맵의 텍셀이 부족해 계단과 피터패닝이 눈에 띄는데, 그
구간만 광선으로 바꾸면 접촉 그림자가 선명해진다. 경계 거리는 편집기에서 조절한다.

광선 질의는 SPIR-V 능력을 요구해 런타임 분기가 안 되므로 `mesh.frag` 와 `mesh_oit.frag` 를
`RAY_QUERY_SHADOWS` 정의를 켜고 한 벌 더 컴파일하고, 지원 장치에서만 그 파이프라인을 만든다.
**mesh shader 경로와 고전 VS+FS 경로 양쪽 모두** 변종을 만들며, 경로 추적기가 쓰던 TLAS 를 집합 1
로 그대로 묶어 쓴다.

**이 장비(MoltenVK)에는 광선 추적이 없어 실행 검증을 하지 못했다.** 확인한 것은 두 변종이 유효한
SPIR-V 로 컴파일되고 `RayQueryKHR` 능력이 변종에만 붙는다는 것, 그리고 게이팅이 꺼진 상태에서
래스터 결과가 이전과 픽셀 단위로 같다는 것뿐이다.

### 광선 반사 (선택 경로)

광선 질의를 지원하는 장치에서 거칠기가 상한 이하인 불투명 표면의 **스페큘러 IBL 을 추적한 반사로
바꾼다.** 불투명 패스가 노멀·거칠기와 split-sum 가중치(F·A + B)를 첨부물로 함께 남기고, 컴퓨트가
픽셀마다 GGX 반사 방향 하나를 뽑아 광선 질의로 추적한다. 히트 표면은 경로 추적 적중 셰이더와 같은
`material.glsl` 로 재질을 읽고, 조명 하나를 골라 그림자 광선을 쏘는 직접광과 환경광, 안개까지 같은
함수로 셰이딩한다. 미스는 프리필터 큐브맵을 거칠기에 맞춰 읽어 IBL 이 보던 하늘과 같다.

픽셀당 한 표본이라 잡음이 크므로 모션 벡터로 지난 프레임을 되짚어 누적한다. 3×3 이웃의 YCoCg
분산으로 히스토리를 가두고, 거울에 가까울수록 누적 상한을 낮춰 시점 변화에 빨리 따라오게 한다.
결과에 가중치와 세기를 곱해 HDR 색상에 바로 더하므로 추가 합성 패스가 없다. 경로 추적 모드에서는
그쪽이 반사를 직접 계산하므로 이 패스는 쉰다. `--debug 10` 은 이번 프레임 원본, `11` 은 누적 결과다.

- ponytail: 히트 거리로 반사의 시차를 되짚지 않아 카메라가 옆으로 움직이면 매끈한 면의 반사가
  한두 프레임 끌린다. 반투명은 광선이 그냥 통과한다.

## 환경 조명 (IBL)

환경광은 균일한 색이 아니라 환경 큐브맵에서 온다. 하늘은 **절차적**(천정·지평·지면 그라디언트에
태양 원반)이거나 **`.hdr` 등정방형 파일**이고, 둘 다 512² 큐브맵으로 구운 뒤 세 가지를 더 만든다.

| 자원 | 크기 | 만드는 법 |
| --- | --- | --- |
| 환경 큐브맵 | 512²×6, RGBA16F, 밉 사슬 | 절차적 하늘 또는 등정방형 변환 → blit 로 밉 생성 |
| 조도 큐브맵 | 32²×6 | 반구 코사인 컨볼루션 |
| 프리필터 큐브맵 | 128²×6, 밉 5장 | GGX 중요도 표본 (Karis split-sum) |
| BRDF 표 | 256² | GGX 적분. 환경과 무관해 한 번만 굽는다 |

전부 컴퓨트로 굽고, **환경 설정이 바뀔 때만** 다시 굽는다. 프리필터는 표본 확률에 맞는 환경 밉을
읽어 밝은 태양이 반딧불이로 튀는 것을 막는다. 절차적 하늘의 태양 방향은 **첫 방향광**을 따라가
하늘과 그림자가 어긋나지 않는다.

셰이딩은 `kD·조도·albedo + 프리필터·(F·a + b)` 형태이고, 기존 `환경광` 색과 세기는 여기에 곱하는
**색조 겸 세기**로 뜻이 바뀌었다. 톤 매핑 패스는 아무것도 그려지지 않은 화소(reverse-Z 깊이 0)를
환경 큐브맵으로 채워 배경을 그린다. 파이프라인을 따로 만들 필요가 없다. 경로 추적기의 하늘도 같은
큐브맵을 읽으므로 두 경로가 같은 배경을 본다.

굽기는 이 장비에서 6~7 ms 정도 걸리는 일회성 비용이다. 환경 설정은 장면 파일에 함께 저장된다.

경로 추적 누적은 카메라·장면뿐 아니라 **환경을 다시 구웠을 때와 경로 추적 설정이 바뀌었을 때도**
버린다. 이 조건이 빠지면 표본이 수백 장 쌓인 뒤에는 새 표본이 1/N 밖에 못 섞여 설정을 아무리 바꿔도
화면이 멈춘 것처럼 보인다. 경로 추적 중에는 그림자 아틀라스를 읽지 않으므로 시점별 캐스터를 걸러
그리기 명령을 짜는 CPU 일도 통째로 건너뛴다.

스킨 메쉬는 스킨 컴퓨트가 뽑아 둔 변형 정점으로 오브젝트마다 하위 가속 구조를 세워 현재 포즈를
반영한다. 다만 재생 중인 애니메이터는 매 프레임 장면 리비전을 올려 누적을 계속 버리게 하므로 화면이
1표본짜리 잡음으로 남는다. DLSS Ray Reconstruction 이 이 경우를 맡는다.

컴퓨트가 큐브 면에 쓰려면 스토리지 이미지가 필요한데, 큐브맵은 GLSL 에서 스토리지로 못 쓴다.
그래서 면을 층으로 보는 `image2DArray`(rgba16f) bindless 바인딩을 하나 더 두고, 밉마다 2D 배열
뷰를 만들어 그 슬롯으로 쓴다. 읽기는 `textureCube` 쪽 바인딩을 쓴다.

## Bloom 과 자동 노출

Bloom 은 **임계값을 넘은 부분만** 번진다. 첫 다운샘플에서 `bloomThreshold` 아래를 깎아 내되, 딱 잘라
내면 밝기가 임계값을 오갈 때마다 화소가 깜빡이므로 `bloomKnee` 폭 안에서는 이차 곡선으로 이어 붙인다.
그 뒤 13탭(Jimenez) 다운샘플로 밉 사슬을 만들고, 3x3 텐트 필터로 올라오며 `bloomScatter` 로 섞는다.
톤 매핑은 그 결과를 원본에 **더한다**.

예전에는 임계값이 없어 화면 전체의 흐림을 원본과 `mix` 했다. 그건 번짐이 아니라 소프트 포커스라,
어두운 곳까지 함께 뿌옇게 만들면서 밝은 곳은 도드라지지 않았다.

`emissiveFactor` 는 glTF 규격상 [0,1] 이라 그것만으로는 임계값을 넘길 수 없다. 그래서
`KHR_materials_emissive_strength` 를 읽어 곱한다. `tests/assets/emissive.gltf` 가 강도 12 짜리
정육면체 하나로 이 경로를 확인하는 최소 자산이다.

자동 노출은 **톤 매핑 앞의 HDR 원본**을 1/8 격자로 성기게 훑어 log2 휘도 히스토그램을 만든다.
예전에는 Bloom 의 2단계 밉을 장면 휘도로 재사용했는데, Bloom 에 임계값이 생기면서 그 밉에는 밝은 곳만
남아 노출이 무너진다. 시간축 업스케일이 없으면 화소 수와 디스패치 수가 예전과 정확히 같고, 있으면
표시 해상도를 훑으므로 렌더 배율만큼 늘어난다.

옮기면서 히스토그램 푸시 상수의 C++/GLSL 배치가 어긋나 있던 것도 드러났다. `layout(push_constant)` 는
std430 이라 `ivec2` 가 8바이트 경계로 밀리는데 C++ 은 4바이트에 붙여 두고 있었다. 셰이더가 훑을 범위를
엉뚱한 값으로 읽어 **표본을 하나도 모으지 못했고**, 그래서 자동 노출이 켜져도 아무 일도 일어나지 않았다.
`scalar` 로 맞춰 고쳤다.

렌더 배율을 낮추면 첫 다운샘플의 축소가 정확히 2 배가 아니다. 13탭 커널의 탭 자리를 원본 텍셀이 아니라
**대상 화소**(±0.5, ±1.0) 기준으로 잡아 발자국이 대상 화소를 덮게 한다. 축소가 2 배면 예전과 같은
값이다. 축소가 크면 탭 사이 원본 화소를 건너뛰는 것 자체는 남는다.

## 높이 안개

지수 높이 안개다. 기준 높이에서 밀도가 가장 크고 위로 갈수록 `exp(-감쇠 · 높이차)` 로 옅어진다.
카메라에서 표면까지의 광학 두께를 해석적으로 적분하므로 표본이 필요 없고, 하늘은 무한 거리로 넣어
위쪽은 수렴하고 지평선 아래는 완전히 잠긴다. 불투명·반투명·하늘 패스와 경로 추적의 1차 구간이
`shaders/fog.glsl` 의 같은 함수를 부르므로 두 경로가 같은 안개를 본다. 설정은 장면 파일의
`post` 에 저장된다.

## 경로 추적

하드웨어 광선 추적이 있는 장치에서만 켤 수 있다. 하위 가속 구조는 적재 직후가 아니라 **경로 추적,
광선 그림자, 반사 가운데 하나가 처음 필요할 때** 세운다. 세우기 전에 구조와 스크래치 크기를 재서
남은 GPU 예산을 넘으면 만들지 않고 사유를 편집기와 로그에 남기며 세 기능을 끈다. 예산을 넘겨 세우면
할당이 시스템 메모리로 넘어간 채 빌드가 늘어져 장치를 잃는다. 빌드는 스크래치 합이 256 MB 를 넘을
때마다 제출을 끊어 한 번의 제출이 길어지지 않게 한다. 메쉬 하나가 그보다 크면 그것만 따로 제출한다.
지오메트리가 바뀌면 구조를 버리고 다음 요청 때 다시 잰다. 장면 조명을 그대로 써서 다음 사건 추정으로
직접광을 모으고, 나머지는 코사인 가중 표본으로 확산 반사를 따라간다. 그림자 광선은 페이로드를
따로 두어 경로가 끊기지 않는다.

렌더 설정에서 반사 횟수, 프레임당 표본 수, 표본 상한, 다음 사건 추정과 러시안 룰렛, 반딧불이를
자르는 복사휘도 상한, 하늘 밝기를 조절할 수 있고 누적을 초기화할 수 있다.

## 업스케일

장면은 표시 해상도에 렌더 배율을 곱한 크기로 그린 뒤 확대한다. 방식은 **공간**과 **시간축** 둘로
나뉘고, 렌더러가 이 둘을 서로 다른 지점에 끼운다.

- **공간**(내장 Lanczos-2 + 대비 적응 선명화)은 톤 매핑 **뒤**에서 돈다. 한 프레임만 보므로
  없는 정보를 만들어 내지 못한다. 어느 장치에서나 동작한다.
- **시간축**(내장 TAAU, FSR 3.1, DLSS)은 톤 매핑 **앞**에서 선형 HDR 을 받는다. 노출과 톤 곡선이
  프레임마다 흔들려도 히스토리가 따라 흔들리지 않아야 하기 때문이다. 이 경로에서는 톤 매핑이
  표시 해상도에서 마지막으로 돈다.

### 시간축 업스케일이 요구하는 것

셋 다 같은 입력을 받는다. 벤더 SDK 없이도 그 배관은 이 저장소가 직접 채운다.

- **지터**: Halton(2, 3) 수열로 화소 안에서 표본 위치를 흩는다. 길이는 `8 × 배율²` 이다. 지터는
  NDC 평행이동을 투영 앞에 곱해 넣으므로 깊이와 무관하게 정확히 지정한 픽셀만큼 옮겨진다.
  이번 프레임 투영에만 넣고 지난 프레임 시점 변환에는 넣지 않는다. 두 프레임이 같은 격자 위에
  있어야 모션 벡터가 실제 화면 이동만 담는다.
- **모션 벡터**: 불투명 패스가 색상과 함께 RG16F 대상에 기록한다. mesh shader 경로와 고전 VS+FS
  경로 양쪽 모두 현재와 이전 클립 좌표를 내보낸다. 스킨은 지난 프레임 조인트 행렬로 이전 위치를
  다시 구한다.
- **하늘**: 아무것도 그려지지 않은 화소를 톤 매핑이 아니라 **HDR 색상 대상에서** 채운다. 깊이가
  0(reverse-Z 의 무한 원거리)인 화소만 통과시키는 전체 화면 패스다. 여기서 채워야 업스케일러가
  하늘까지 함께 누적해 실루엣 가장자리에 배경색 테두리가 남지 않는다. 하늘의 모션 벡터는 방향
  벡터를 지난 시점으로 되쏘아 카메라 회전분만 담는다. 덤으로 반투명이 하늘 위에 합성된다.
  전에는 톤 매핑이 하늘로 덮어써서 하늘을 등진 반투명이 지워지고 있었다.

경로 추적을 켜면 시간축 업스케일은 꺼진다. 누적 버퍼가 이미 표본을 쌓고 있어 서로 겹치고, 지터를
넣으면 카메라가 바뀐 것으로 보여 누적을 매 프레임 버리게 된다.

### 내장 시간축 업스케일 (TAAU)

표시 해상도 히스토리를 모션 벡터로 재투영해 쌓는다. 벤더 SDK 가 없는 곳(macOS 포함)에서 쓸 수
있는 유일한 시간축 경로다.

- 3×3 이웃을 **표시 화소 기준** 가우시안으로 모은다. 렌더 화소 기준으로 재면 확대 배율만큼
  넓어져 여러 프레임을 쌓아도 한 프레임의 흐림이 그대로 남는다.
- 히스토리는 YCoCg 이웃 분산(평균 ± 1.25σ)으로 가둔다. 최소/최대로 자르는 것보다 좁아 잔상이 덜
  남는다. 재투영 변위는 이웃에서 **가장 가까운** 화소 것을 쓴다.
- 섞는 비율은 고정값이 아니라 히스토리 알파에 담긴 표본 수의 역수다. 처음 몇 프레임이 빠르게
  채워지고 상한(배율에 따라 8~64)에 닿은 뒤 지수 이동 평균이 된다.
- 표본은 `c / (1 + max(c))` 로 눌러 평균을 낸 뒤 되돌린다. 밝은 표본 하나가 평균을 지배해
  반딧불이로 남는 것을 막으면서도 결과가 어두운 쪽으로 치우치지 않는다.

### FSR 3.1

AMD FidelityFX API 를 그대로 쓴다. SDK 는 vcpkg 처럼 고정 태그로 `external/fidelityfx` 에 성긴
체크아웃하며, 받는 것은 헤더와 서명된 `amd_fidelityfx_vk.dll` 뿐이다. SDK 를 통째로 빌드하면 셰이더
순열을 수천 개 컴파일해야 하는데 우리가 쓰는 것은 그 DLL 하나다.

DLL 은 **링크하지 않고 실행 시점에 찾는다**(`LoadLibrary` + `GetProcAddress`). 없으면 편집기에서
FSR 항목만 비활성으로 나오고 나머지는 그대로 돈다. `-DCG_LAB_FSR=OFF` 로 통째로 뺄 수도 있고,
Windows 가 아니면 자동으로 꺼진다.

FSR 4 를 위해 따로 붙일 것은 없다. FidelityFX API 는 같은 진입점으로 하드웨어에 맞는 구현을
고르므로, RDNA4 와 충분히 새 드라이버에서는 이 자리에 FSR 4 가 들어온다.

넘기는 값 중 규약을 맞춰야 하는 것:

- 색은 톤 매핑 앞의 선형 HDR 이라 `ENABLE_HIGH_DYNAMIC_RANGE` 를 켠다.
- 깊이는 reverse-Z 무한 원거리라 `ENABLE_DEPTH_INVERTED` 와 `ENABLE_DEPTH_INFINITE` 를 켠다.
- 모션 벡터를 화면 UV 로 담았으므로 `motionVectorScale` 에 렌더 해상도를 넣어 픽셀 단위로 되돌린다.
  방향은 현재에서 이전으로, FSR 이 기대하는 것과 같다.
- 생성 서술자에 엮은 포인터는 컨텍스트를 지울 때까지 살아 있어야 해서 멤버로 들고 있는다.

**`VK_KHR_get_memory_requirements2` 를 장치에 켜야 한다.** 1.1 에서 코어로 올라간 확장이지만
`vkGetDeviceProcAddr` 은 확장을 명시적으로 켠 경우에만 `KHR` 접미사 별칭을 돌려준다. FidelityFX
백엔드는 `vkGetBufferMemoryRequirements2KHR` 을 그 이름으로 찾아 **가드 없이** 부르므로, 켜 두지
않으면 컨텍스트 생성 중에 널 포인터를 호출하고 프로세스가 죽는다.

**`shaderInt16` 과 `storageBuffer16BitAccess` 도 켜야 한다.** FSR 셰이더가 SPIR-V `Int16` 능력을
선언해서, 켜 두지 않으면 셰이더 모듈 생성이 거부된다.

검증 레이어를 켜면 FSR 이 내부 `rw_luma_history` 를 `rgba8` 로 선언하고 rgba16f 뷰에 묶는다는
경고가 나온다. 벤더 DLL 안쪽이라 이 저장소에서 고칠 수 있는 것이 아니고, 실행에는 지장이 없다.

### DLSS

NVIDIA NGX 를 쓴다. **SDK 는 자동으로 받지 않는다.** 재배포 조건이 붙은 SDK 라 받을지 말지는 쓰는
쪽이 정할 일이다. [NVIDIA/DLSS](https://github.com/NVIDIA/DLSS) 를 받아 경로를 넘기면 켜진다.

```sh
cmake --preset debug -DCG_LAB_DLSS_SDK=<받은 경로>
```

경로를 주지 않으면 DLSS 만 빠지고 나머지는 그대로 빌드된다. `--upscaler 4` 로 켜려 해도 사유를
남기고 내장 공간 업스케일로 돌아간다.

FSR 과 다른 점 셋:

- **NGX 는 확장을 요구하고, 그건 인스턴스와 장치를 만들 때만 켤 수 있다.** 그래서
  `NVSDK_NGX_VULKAN_RequiredExtensions` 를 장치 생성 전에 부르고 결과를 확장 목록에 얹는다.
  다만 `VK_EXT_buffer_device_address` 는 빼야 한다. 코어 1.2 기능으로 이미 켜 두었는데 승격 전
  확장을 함께 켜는 것은 규격 위반이라 장치 생성이 거부된다.
- **기능 생성이 명령 버퍼를 요구한다.** `resize` 는 명령 버퍼 밖이라 만들 수 없어, 크기만 적어
  두고 다음 평가 때 만든다.
- **NGX 정리는 장치가 살아 있을 때 해야 한다.** 정적 소멸자에 맡기면 이미 없어진 장치를 붙들고
  종료 중에 죽고, 그 전에 Vulkan 객체 400여 개가 새어 나간다. 렌더러 소멸자에서 명시적으로 끈다.

렌더 배율이 이미 해상도를 정하므로 NGX 에는 그 배율에 가장 가까운 사전 설정(DLAA / 품질 / 균형 /
성능 / 울트라 성능)을 알려 준다.

디버그 빌드도 `lib/Windows_x86_64/rel` 의 가중치 DLL 을 쓴다. `dev` 쪽은 화면 한가운데에 배포 금지
워터마크를 그려서 렌더 결과를 눈으로 보는 데 방해가 된다. NGX 쪽을 진단할 일이 있으면 그 DLL 로
바꿔 넣으면 된다.

## 자동 튜닝

기동할 때 장치 종류·장치 메모리·광선 질의 유무·mesh shader 유무와 표시 해상도를 보고 등급(낮음·중간·
높음)을 매겨 렌더 배율, 업스케일러, 그림자 캐스케이드, SSAO 표본, 광선 반사·광선 그림자, 유체 입자
상한의 기본값을 정한다. 판정과 그 근거는 로그와 렌더 설정의 «하드웨어» 절에 그대로 나온다. 고른 뒤에는
평범한 설정이라 편집기에서 자유롭게 고칠 수 있다.

등급은 **장치 힙의 크기**로 가른다(외장 6GB 이상 높음, 3GB 이상 중간). 남은 예산이 아니라 크기여야
같은 기계가 실행마다 같은 등급을 받는다. 내장 그래픽은 대역폭을 CPU 와 나눠 쓰고 보고하는 메모리가
외장과 견줄 수 없어 늘 낮은 등급이다. 모니터가 1440p 보다 넓으면 한 등급 내린다.

`--auto-tune` 이 세기를 정한다. `off` 는 아무것도 바꾸지 않고, `safe`(자동 튜닝의 기본)는 프레임을
지키는 쪽, `aggressive` 는 화질을 더 올린다. **명령줄에서 명시한 항목은 덮지 않는다** — `--render-scale`,
`--upscaler`, `--reflections`/`--no-reflections` 를 주면 그 값이 이긴다.

높은 등급에서는 `safe` 로도 광선 반사가 켜진다. 그러면 첫 프레임에 하위 가속 구조를 세우므로, 그 비용이
싫으면 `--no-reflections` 나 `--auto-tune off` 를 준다.

판정 함수 `gfx::chooseProfile` 은 Vulkan 을 타지 않는다. 하드웨어 사실을 구조체로 받아 설정을 돌려주므로
`hardware_profile` 테스트가 저·중·고 등급을 손으로 만들어 확인한다.

## 프레임 CPU 작업의 병렬화

오브젝트가 만 개를 넘어가면 프레임 시간의 대부분이 GPU 가 아니라 «명령을 만드는 CPU» 로 간다. 오브젝트
2 만 개짜리 장면(`--auto-tune off --no-colliders`, RTX 3060 · 12 스레드)에서 `--profile` 로 잰 값이다.

| 구간 | 전 | 후 |
| --- | --- | --- |
| 장면 정리(`Scene::refresh`) | 0.90 | 0.32 |
| 그리기 명령 구성 | 3.40 | 2.32 |
| ├ 인스턴스 구성 | 1.85 | 1.41 |
| └ 그림자 드로우 구성 | 1.16 | 0.43 |

네 가지를 고쳤다.

**작업 큐가 잠들기 전에 잠깐 돈다**(`src/core/job_system.cpp`). 프레임마다 `parallelFor` 를 수십 번
부르고 그 사이 간격이 마이크로초 단위인데, 매번 조건 변수로 재우고 깨우면 그 값이 작업 자체보다
비쌌다. 워커가 512 번쯤 큐를 더 보고 나서 잠들게 하고, **자는 워커가 없으면 `notify_all` 도
건너뛴다.** 이 하나로 나머지 병렬화가 비로소 이득이 된다(그 전에는 400 KB 짜리 복사를 나누면 오히려
느려졌다). 조건 변수가 **시간 제한으로** 돌아왔으면 여전히 할 일이 없다는 뜻이므로 도는 몫을 되돌리지
않는다. 그러지 않으면 «1 ms 잠 → 512 번 돌기» 를 되풀이해 쉬는 동안 워커마다 코어를 태운다.
`sleepers` 는 `seq_cst` 다. 깨우기를 건너뛰는 판단과 자러 가는 판단이 서로의 옛 값을 보면 그 한 번의
`parallelFor` 가 혼자 도느라 느려진다(부르는 쪽이 큐를 직접 비우므로 멈추지는 않는다).

**세계 변환을 깊이 단계로 나눠 푼다**(`Scene::refresh`). 부모를 거슬러 올라가는 재귀와 «이미 풀었다»
표식을 없애고, 오브젝트를 깊이 순으로 늘어놓아 단계마다 워커에 나눈다. 같은 단계끼리는 서로를 보지
않고 부모는 앞 단계에서 이미 끝나 있다. 깊이 순서는 **계층이 바뀐 프레임에만** 다시 만든다.
순환 부모는 편집기가 막지만 손으로 고친 파일이 들어와도 뿌리로 보고 넘어간다.

**오브젝트마다의 판단을 한 번만 한다**(`Renderer::buildDrawCommands`). 명령을 세는 패스와 자리를
배정하는 패스가 각각 메쉬 → 재질로 두 번 건너뛰는 조회를 하고 있었다. 그 판단을 워커에 나눠 미리
뽑아 두고 두 직렬 패스는 그 배열만 훑는다. 자리 배정은 버킷 커서를 순서대로 밀어야 해서 직렬로 남는다.

**그림자 절두체 판정을 시점이 아니라 오브젝트로 나눈다**. 캐스케이드가 넷뿐이라 시점으로만 나누면
워커 넷만 일했다. «오브젝트 전체 × 시점 전체» 를 한 번에 돌려 비트 표를 만들고, 시점별 압축은 그
표를 읽기만 한다.

여기에 더해 매핑된 버퍼로 붓는 복사(인스턴스·그리기 명령)와 지난 변환 갱신을 워커에 나눴다. 쓰기 결합
메모리라 한 스레드로는 대역폭을 다 못 쓴다.

측정해서 이득이 없어 **넣지 않은 것**도 적어 둔다. 미사용 모델 수집의 O(오브젝트 × 모델) 선형 탐색은
내장 모델이 여덟 개뿐이고 계층이 바뀐 프레임에만 도는 데다, 잰 값이 마이크로초라 그대로 두었다.

## 렌더 그래프

`Renderer::recordCommands` 는 프레임의 패스를 `gfx::RenderGraph`(`src/gfx/render_graph.h`) 의 노드 목록으로 짠다.
노드는 이름·프로파일러 구간·`enabled` 조건·이미지 사용 선언(`reads`/`writes`/`leaves`)·기록 람다다. **노드는 조건과
무관하게 늘 등록하고 `enabled` 가 실행을 정한다.** 그래야 플러그인이 `addAfter("스킨", …)` 로 끼울 앵커가 늘 있고,
래스터·Path Tracing 의 갈림과 업스케일 두 경로(시간축은 톤 매핑 앞, 공간은 뒤)가 노드 조건 하나로 표현된다.

이미지 레이아웃은 그래프가 **이미지 전체 단위**로 추적한다. 노드가 선언한 사용(레이아웃·단계·접근)으로 앞 상태에서의
전이 배리어를 만들고, 같은 레이아웃의 읽기가 이어지면 배리어를 내지 않는다. 상태는 프레임을 넘어 남아 «지난 프레임 톤
매핑이 읽던 것을 이번 업스케일이 덮어쓰는» 전이도 맞는다. `discard` 사용은 옛 레이아웃을 UNDEFINED 로 두어 프레임마다
처음부터 채우는 대상(색상·깊이·OIT·톤 매핑 대상)이 내용을 보존하지 않게 한다. 렌더 대상을 다시 만들면
`resetStates()` 로 전부 UNDEFINED 가 된다.

층·밉 단위 전이(그림자 아틀라스, HZB, Bloom)와 컴퓨트가 도로 첨부물로 돌려 놓는 것(반사, 물 표면)은 패스 안에 남고,
그런 노드는 `leaves` 로 자기가 남긴 상태를 그래프에 알린다. 스왑체인 이미지는 프레임마다 새로 받으므로 추적하지 않는다.
순서는 등록 순서 하나뿐이다 — DAG 정렬은 두 경로의 갈림을 `enabled` 로 다 표현할 수 있어 두지 않았다.

## 플러그인

기능은 `app::Plugin`(`src/app/plugin.h`) 으로 붙인다. 훅은 셋이다: `build(Services&)` 는 기동 시 한 번(자원 생성, 렌더
패스 등록, 옵션·하드웨어 프로파일 읽기), `update(Services&, dt)` 는 프레임 앞(`scene.update` 뒤, `renderer.prepareFrame`
앞), `ui(Services&)` 는 편집기 «렌더 설정» 창의 절이다. `Services` 는 장면·작업 큐·옵션·프로파일·설정의 참조와 gfx 객체·편집기의
포인터 묶음이라 플러그인은 그것으로만 다른 계층을 본다. 포인터는 헤드리스에서 null 이다. `Application::registerPlugins` 의 **등록 순서가 호출 순서**다.

렌더 패스는 `Renderer::addPass` 로 끼운다. 훅은 프레임마다 `recordCommands` 가 자기 노드를 다 넣은 뒤 불리고,
`graph.addAfter(앵커, 노드)` 로 자리를 고른다. `PhysicsPlugin` 이 그 예다 — GPU 강체 솔버(`gfx::RigidBodySimulator`)를
소유하고 «스킨» 뒤에 «강체» 노드를 끼운다.

지금 플러그인: 물리(CPU 스텝·GPU 솔버·«물리» 절), 유체(입자 상한·«유체» 절), 디버그 선(`--no-colliders`·«콜라이더
표시» 절), 프로파일러(`--profile`·«프로파일러» 절·종료 시 로그). 그림자·SSAO·반사·IBL·컬링·Upscaling·Path Tracing 절은
Renderer 필드만 만지므로 편집기(`editor.cpp`)에 그대로 있다 — 수명 주기가 없는 값 묶음을 플러그인으로 감싸면 구현
하나짜리 인터페이스만 생긴다.

헤드리스(`--headless`)는 창·Vulkan·렌더러·편집기를 만들지 않고 같은 플러그인 목록으로 `update` 만 돈다. 내장 도형과
장면 파일의 모델은 메쉬 콜라이더용 CPU 사본만 남고 메쉬 번호는 콜라이더 표 끝에 이어서 매긴다. `ctest -R
headless_physics` 가 `tests/scenes/rigid_cpu.json` 을 120 프레임 돌려 `tests/scenes/expected/rigid_cpu_120.json` 과
바이트로 견준다 — 강체 솔버를 고치면 기준 파일도 같이 갱신한다.

## 하드웨어 기능 게이트

렌더 모드별로 필요한 Vulkan 기능을 기동 시 조회하여, 지원되는 모드만 활성화한다. 미지원 기능에 대한
소프트웨어 폴백 경로는 제공하지 않는다. 예를 들어 MoltenVK 에는 `VK_EXT_mesh_shader` 와
`VK_KHR_ray_tracing_pipeline` 이 없으므로 macOS 에서는 고전 파이프라인 경로만 사용할 수 있다.

예외 하나는 `gl_DrawID` 다. MoltenVK 는 `shaderDrawParameters` 를 지원한다고 보고하지만 MSL 에
`DrawIndex` 가 없어 SPIR-V 변환에서 죽는다. `VK_KHR_portability_subset` 을 내거는 장치에서는 정점
셰이더를 `gl_DrawID` 없는 변종(`mesh_nodrawid.vert.spv`)으로 바꿔 끼운다. 그 값은 meshlet·LOD
디버그 뷰에만 쓰이므로 렌더 결과는 같다. 편집기는 그 장치가 만들지 못하는 디버그 뷰(이 둘과, 광선
질의가 없을 때의 반사 뷰)를 콤보에서 잠그고 사유를 보인다(`Renderer::debugModeBlockedReason`).

**시뮬레이션은 예외다.** 그 원칙은 «어떻게 보이는가» 를 정하는 렌더 경로에 대한 것이고, 시뮬레이션은
어디서 풀든 결과가 같아야 하는 계산이라 사용자가 백엔드를 고른다. 유체는 GPU 컴퓨트와 CPU SPH 를 모두
갖추고 부품마다 고를 수 있으며, `자동` 은 GPU 를 쓰되 만들지 못하면 CPU 로 내려간다. 강체도 CPU 순차
임펄스와 GPU Jacobi 를 모두 갖추되 `자동` 은 CPU 다 — 수치가 갈리는 쪽이라 고른 사람만 GPU 로 간다.
컴퓨트 파이프라인을 만들지 못한 장치에서는 콤보의 `GPU` 항목이 잠기고 사유가 뜬다.

**한 장면에서 두 백엔드를 섞지 않는다.** 솔버가 자기 백엔드의 물체만 모으므로 CPU 강체와 GPU 강체는
서로 부딪히지 않는다. 공만 `GPU` 로 바꾸면 `자동`(=CPU) 바닥을 그대로 통과한다. 인스펙터가 그 사실을
적어 두고, `tests/scenes/rigid_cpu.json` 과 `rigid_gpu.json` 이 같은 배치를 백엔드만 달리해 담고 있다.

```sh
./build/release/cg_lab --open tests/scenes/rigid_cpu.json --play --screenshot cpu.png --screenshot-frame 240
./build/release/cg_lab --open tests/scenes/rigid_gpu.json --play --screenshot gpu.png --screenshot-frame 240
```
